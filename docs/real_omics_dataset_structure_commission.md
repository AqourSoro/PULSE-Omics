# PULSE-Omics：公开真实数据的逐文件结构研究与合成数据可行性研究委托书

## 一、任务与优先级

请作为熟悉纵向多组学、生物统计、临床队列、质量控制、数据工程和生成模型的高级独立研究者，直接接管 GitHub 仓库 **AqourSoro/PULSE-Omics** 的现有 **omics** 分支。研究对象是目前已下载的真实数据文件本身。

**按以下顺序完成工作，不能用规划或数据规范设计代替实际调查：**

1. 完成尚未成功的公开真实数据获取；保留已成功下载的数据，不重复下载。
2. **逐个打开现有真实文件，研究其确切结构、字段、观测值、科学含义、组织方式、采样时间和跨组学对应关系。** 根据真实内容计算可用数据规模。
3. 在真实数据调查完成之后，研究能否构建满足研究要求、具备可检查真值的合成纵向多组学数据，以检验 PULSE 框架的具体机制。

本轮核心交付是 **真实数据的完整实证结构报告**。不要预先抽象为自拟的 participants/visits/specimens 等标准表，再用自拟格式取代原始数据的描述。标准化转换只能在原始结构已逐字段核实后提出。

## 三、逐文件科学结构研究：必须实际打开并记录的内容

对于每一个 **CSV、TSV、TXT、Excel 工作簿及其每个工作表、BIOM 矩阵**，给出独立的原生结构说明，至少包括：

1. **文件与来源**：数据集名称、原始 URL/DOI、文件完整名称、大小、哈希、公开许可、处理版本、是原始测量还是作者处理后的结果。
2. **表格结构**：真实工作表名称、表头行号、说明行/注释行、有效行列范围、行列方向（样本 × 特征 / 特征 × 样本）、维度、数据类型、所有非特征元数据列的原始名称和定义。
3. **记录语义**：一行/一列究竟代表一名患者、一次访视、一份生物样本、一次上机重复、一个蛋白质/代谢物，还是汇总统计。列出三个匿名化真实结构示例，说明它们之间的关系。
4. **身份关系**：患者 ID、样本 ID、检测 ID、批次 ID 的命名规则；跨文件关联字段及实际匹配数、重复和不匹配记录。对照文件需独立解析，禁止按行顺序构造连接。
5. **时间结构**：日期、相对小时/天、T1/T2、基线/随访、干预/治疗/感染事件；记录真实时间单位、参照点、时间分辨率及缺失状况。
6. **生物学测量**：血浆、血清、粪便、尿液等材料；宿主/微生物来源；测量平台与协议；蛋白质/代谢物特征 ID、实体注释、单位、对数或归一化尺度、数值范围、同名不同平台的意义。
7. **缺失及质量**：整模态未测量、特征级 NA、低检测限、技术批次、QC 剔除、可疑重复、常数特征、仅部分时刻检测；分别给出实际频数与分母。
8. **真实纵向可用性**：独立参与者数、各人采样次数分布、真实时间间隔分布、有蛋白质组/代谢组的访问数、同次双组学交集，至少两次和至少三次**均有双组学**的受试者数；逐数据集计算并列出不能配对的原因。
9. **代码读入示例**：展示用原始文件（不是凭空转换后的假想 CSV）读取一个真实矩阵和相应元数据的方法；给出结果形状、索引名、代表性字段。保留准确的原有语义。

对超过千个组学特征的宽表，正文说明命名规律、注释来源、典型特征和总数；另提供机器可读的完整列名字典（字段/特征 ID、原名称、所属原始文件及工作表、列序、单位与变换，有证据的才填写）。不要仅列出“464 维”“1050 维”而不解释具体特征代表什么。

## 四、完成原始结构研究后的跨队列分析

在逐文件研究完成后，对照现有 PULSE 模型实现 pulse/data/dataset.py、pulse/model.py、pulse/training/trainer.py 及训练脚本，实证说明：

- 哪些队列可以构成**同一受试者的纵向双组学联合观测**，哪些只能构成某次访问的配对，哪些只提供单模态、汇总或不完整时间信息。
- 每个队列能支持哪项具体任务：同次缺失组学补全、利用历史做当前缺失组学补全、未来真实时间点预测、干预前后变化研究。
- 原始文件中必须保留哪些标识、尺度、观测掩码、真实时间字段，现有 PULSE 哪些接口已支持、哪些确实需要改动。
- 给出**原始字段 → 可训练变量**的一一映射和明确的原始值处理原则，包括 train-only 归一化、缺失特征处理、按患者分割、防止跨队列共享 ID 冲突。

这一阶段可以确定数据兼容性和后续整理方式，但不能提前把抽象统一 schema 当作具体原始数据研究的结果。

## 五、真实数据研究完成后才开展的合成数据研究

基于已经测得的真实数据类型、时间间隔、个体差异、组学特征分布、检测尺度和缺失特点，研究以下问题：

1. PULSE 的具体待验证命题是什么：历史观测是否提供相对于当前观测的增量信息；两模态是否确有由共同潜在状态解释的结构；缺失时能否恢复真实潜在状态/观测；状态发生变化时模型是否跟随。
2. 合成数据需要包含哪些可知的真值：个体参数、潜在生理状态 z_i(t)、外部干预 u_i(t)、非等间隔时间 t、两种组学观测函数和噪声、实际观测与缺失掩码。生成机制应能产生可检验的相关性、时间依赖、跨组学信息和状态变化。
3. 比较合理的生成路线：可解释潜在动力系统、已知网络/路径约束的模拟、真实数据估计观测分布的半合成方法。调查相应真实文献与开源实现，明确模型假设、适用规模和可以检验的科学问题。
4. 设计能判别 PULSE 历史状态机制的实验：有历史/无历史、当前模态有/无、时间乱序、历史来自其他个体、动态状态转换与分布漂移、MCAR/MAR/MNAR 缺失；度量真实潜在状态恢复和持出观测的预测误差。
5. 明确如何避免自证：如果合成数据生成机制与 PULSE 架构同构，模型表现可能只是适配该生成器；必须加入机制不同的生成器、基线和独立参数组合；用真实数据确定可模拟的范围。
6. 最终裁决 **是否应该生成、生成什么数据、能验证哪些科学命题、不能验证哪些命题**，并提供可执行生成方案与参数定义。本轮**先完成研究设计，不启动大规模合成数据生产或 GPU 训练**。

## 六、最终交付与实际完成标准

提交到 omics 分支，所有研究结论要能追溯到原始数据文件、工作表、列/行位置、源论文或数据说明；具体成果至少包含：

1. **真实数据下载结果与来源清单**：逐数据集列已下载/失败/受控状态、精确文件名、大小、哈希、失败原因及已成功替代源。
2. **逐文件逐工作表的数据结构研究报告**：解释实际观测单元与每个重要字段，记录表头、数据类型、单位、数值语义、特征类型与维度；对 CSIRO 9 个文件尤其不得遗漏 005 编号对照表。
3. **完整原始字段与特征目录**（机器可读）及逐源读取实例。全部字段来自实际文件，不使用假想列名填充。
4. **样本配对与纵向统计报告**：真实关联字段、无法关联清单、双组学配对访问数、两次/三次以上真实联合采样患者数、时间间隔、缺失与批次分布。
5. **PULSE 数据适配研究**：明确原始数据及测量事实如何映射到 PULSE 实际输入、训练和评测，不提前实现大型重构。
6. **合成数据科学研究与实验方案**：建立在前四项真实结果之上，包含已知真值、生成机制、对照组和判别指标。
7. **提交记录**：仅必要的研究脚本、文档和小型非敏感统计结果进入 GitHub。真正原始数据、个体级组学矩阵、模型训练产物留在 F 盘。

拒绝以抽象的“标准数据结构设计”“已找到下载链接”“建议更多数据”“下一步可以考虑”替代以上实证交付。已正确获取的文件无需重复下载；遇到单个源受限时，先完成其他现有文件的结构调查。全过程以文件内容和真实数据统计为准，不预设研究结论。
